## 📁 피드백 대상 : Kmeans
**1. 라벨 생성에 사용한 변수로 다시 분류 학습하는 구조 점검 필요**

현재 train_labeled.csv에는 K-means 군집화에 사용한 Q변수(Q1~Q31, AI 관련 변수 등)가 그대로 남아 있고, 여기에 digital_stage 라벨만 추가된 상태입니다.

문제는 이후 분류 모델에서도 동일한 Q변수들을 입력(X)으로 사용해 digital_stage를 예측하면, 모델이 실제 패턴을 학습하는 것이 아니라 “K-means가 이미 나눈 기준”을 그대로 외우게 된다는 점입니다.

이 경우 정확도가 거의 100% 가까이 나올 수 있는데, 실제 예측 성능이라기보다는 이미 만든 답을 다시 맞히는 구조에 가까워집니다.

다만 군집화 단계에서 연령·성별·학력·소득·지역 같은 demographics 변수를 제외한 건 좋은 설계라고 생각됩니다. 이 의도를 살리려면 분류 모델에서는 오히려 “군집화에 사용하지 않은 변수들”만 입력으로 사용하는 방향이 더 적절해 보입니다.

예시)

입력(X): 연령, 학력, 소득 등 demographics
예측(Y): digital_stage

이렇게 하면 “어떤 사회적 특성이 디지털 단계에 영향을 주는가”를 설명하는 모델로 의미가 생길 것 같습니다.

→ 팀 내에서 “분류 모델 입력값(X)을 무엇으로 할지” 한 번 명확히 정리해보는 것이 좋을 것 같습니다.

**2. Scaler / K-means fitting 과정에서 데이터 누수(leakage) 가능성**

현재 Cell 7, 9에서는 StandardScaler.fit_transform()과 KMeans.fit()을 train + val + test 전체 데이터에 적용한 뒤 다시 split을 나누고 있습니다.

이 경우 test 데이터의 평균/분산 정보와 군집 중심 정보가 학습 과정에 이미 들어가게 되어, 이후 분류 모델 평가가 공정하지 않게 됩니다.

권장 방식은 다음과 같습니다.

train 데이터로만 scaler와 KMeans 학습(fit)
val/test에는 transform만 적용
군집 라벨은 train에서 만든 중심 기준으로 predict

즉, test 데이터를 “처음 보는 데이터” 상태로 유지하는 것이 중요합니다.

현재 검증 방식은 ‘정의 반복’에 가까울 수 있음

현재 stage_score_summary에서는 단계가 올라갈수록 digital_activity_score가 증가하는 것을 군집 검증 근거로 사용하고 있습니다.

다만 이 점수 자체가 군집화에 사용한 Q변수들로 계산된 값이기 때문에, 어느 정도 단조 증가하는 것이 자연스러운 구조입니다.

실제로 cluster_activity_ranking_helper.csv와 stage_score_summary.csv의 수치가 거의 동일하게 나타나고 있습니다.

-0.626 → -0.166 → 0.347 → 0.63

즉 현재 방식은 “군집이 잘 만들어졌는지 검증”이라기보다, “군집 생성 기준을 다시 확인한 것”에 가까울 수 있습니다.

오히려 군집화에 사용하지 않은 외부 변수로 검증하면 더 설득력 있는 결과가 될 것 같습니다.

예시)

단계가 높아질수록 평균 연령 감소
학력 증가
소득 증가

이런 식의 경향성이 나타나면 face validity 측면에서 설명력이 높아질 것 같습니다.

**3. 현재 변수 구조가 K-means와 완전히 잘 맞지 않을 가능성**

현재 입력 변수에는 다음과 같은 서로 다른 형태의 데이터가 함께 들어가 있습니다.

0/1 이진 변수
리커트 척도
다중응답 더미 변수

K-means는 유클리드 거리 기반 알고리즘이라, 이런 형태의 변수들이 한꺼번에 들어가면 거리 계산이 왜곡될 수 있습니다. 특히 0/1 더미 변수가 많으면 특정 응답 패턴만으로 군집이 갈릴 가능성도 있습니다.

현재 실루엣 점수가 약 0.08 수준으로 낮게 나온 이유도 이와 관련 있을 수 있어 보입니다.

개선 방향으로는 다음 방법들을 고려해볼 수 있을 것 같습니다.

PCA / 요인분석 후 군집화
혼합형 데이터용 k-prototypes
Gower distance 기반 방법

혹은 단순하게라도 “군집 구분에 정말 필요한 변수만 남기기”를 먼저 시도해봐도 좋을 것 같습니다.

**4. 일부 변수는 ‘디지털 적응 수준’과 단조 관계가 아닐 가능성**

현재 digital_activity_index는 아래 4개 영역만 사용합니다.

기기 접근
기본 역량
서비스 이용
AI 활용

반면 실제 K-means에는 Q20~31 등 다양한 변수 블록이 추가로 들어가 있습니다.

그런데 이 중 일부 변수들은 “디지털 적응 수준”과 단순 비례 관계가 아닐 수 있습니다.

예를 들어:

디지털 사용이 많은 사람이 오히려 불편 경험도 더 많이 느낄 수 있음
AI를 많이 사용하는 사람이 정책 요구도 더 많을 수 있음

즉 “활용 수준 ↑ = 어려움 ↓” 구조가 항상 성립하지 않을 수 있습니다.

특히 Q28(AI 미이용 이유)는 AI 미사용자에게만 의미 있는 변수라서, skip 패턴 자체가 군집을 인위적으로 나누는 원인이 될 가능성도 있습니다.

이런 변수들이 함께 들어가면 군집의 중심 축인 “디지털 적응 수준”이 흐려질 수 있고, 특히 2단계와 3단계 구분이 모호해지는 원인이 될 수 있을 것 같습니다.

→ 군집화에는 우선 “적응 수준과 비교적 단조 관계를 가지는 변수들”만 사용하는 방향도 검토해보시면 좋을 것 같습니다.
